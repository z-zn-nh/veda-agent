# 00 产品边界

## 1. 产品定义

目标是一个以 Agent 能力为核心、同时具备独立笔记和独立白板工具的工作区应用。

Agent、笔记、白板不是“一个主应用加两个弹窗”，而是三个可以独立使用的能力：

- Agent：面向任务、对话、工具调用和持续执行。
- 笔记：面向用户个人记录、编辑、整理和检索。
- 白板：面向自由布局、视觉组织、原生画布创作和内容引用。

Agent 可以读取和写入笔记、白板，但笔记和白板的基本功能不能依赖 Agent 存在。

## 2. 工作区

所有内容归属于 `Workspace`：

- 可以绑定代码目录，也可以不绑定代码目录。
- 可以只用于笔记。
- 可以只用于白板。
- 可以同时拥有 Agent 会话、笔记、白板、附件和工具状态。

工作区是用户可理解的内容归属边界。不要再暴露两个含义相近的“项目/知识库/空间”概念，除非界面能明确解释它们的区别。

建议基本身份：

```ts
type WorkspaceId = string;
type PaneId = string;
type NoteId = string;
type BoardId = string;
type SessionId = string;
```

## 3. 独立工具要求

### 笔记

- 没有 Agent 时可创建、编辑、保存、重开和搜索。
- 支持多个笔记面板并排。
- 笔记正文有唯一真源。
- 外部修改、Agent 修改和本地编辑发生冲突时不能静默覆盖。

### 白板

- 没有 Agent 时可创建、编辑、保存、重开和组织对象。
- 可以直接创建文本、便签、图形、连线、图片和其他原生画布对象。
- 可以引用笔记，但引用不是白板存在的前提。
- 删除引用只删除引用对象，不删除目标笔记。
- 目标笔记失效时保留占位和恢复入口。
- 支持多个白板面板并排。

### Agent

- 可以读取工作区中的笔记和白板结构。
- 可以通过正式工具修改笔记和白板，不直接操作 UI 状态或底层数据库。
- 会话状态独立于 GUI 面板，面板关闭不等于会话终止。
- TUI 与 GUI 最终连接同一个会话执行器。

## 4. 布局要求

以下都必须由同一套布局模型支持：

- 单栏：一个 Agent、一个笔记或一个白板。
- 双栏：笔记 + 白板、Agent + 白板、笔记 + 笔记等。
- 多栏：Agent + 笔记 + 白板，或多个同类面板。
- 横向和纵向分割。
- 调整比例、关闭面板、重新打开面板和恢复布局。

不能通过 `showNote`、`showBoard`、`showAgent` 等布尔值拼接布局。建议使用分割树或等价的数据结构。

## 5. 明确不做的假设

- 不假设新项目沿用旧产品名。
- 不假设桌面容器已经确定。
- 不假设 pi 已经提供共享 GUI/TUI 会话 API。
- 不假设白板只是笔记卡片容器。
- 不假设用户一定先启动 Agent。
- 不假设首版只有左右两栏。
