# 06 旧能力迁移边界

## 1. 总原则

新项目重新设计宿主，不等于旧项目所有代码都作废；也不等于旧项目可以整体复制。

按“能力”迁移，按“接口”重新接入，按“数据契约”验证。旧项目只作为参考、样本和对照，不作为新宿主的架构中心。

## 2. 推荐保留的能力

### 编辑器

可评估保留：

- Tiptap/Markdown 内容转换。
- 富文本 Schema 和编辑交互。
- 大纲、链接、表格、代码、数学等编辑扩展。
- 编辑器局部样式和只读预览逻辑。

迁入要求：

- 编辑器不能拥有新的全局路由。
- 编辑器不能直接管理工作区导航。
- 编辑器保存通过 `NoteService` 或等价应用服务。
- 编辑器的 Portal、快捷键和主题通过宿主适配。

### 画布

可评估保留：

- Konva 或等价渲染算法。
- 画布坐标、缩放、拖拽、选择和缩放计算。
- 连线、卡片、思维导图等交互算法。
- 画布对象的序列化和反序列化工具。

迁入要求：

- 画布必须支持原生对象与引用对象两类模型。
- 画布不能假设唯一活动白板。
- 画布快捷键只能作用于活动面板。
- 画布不能直接操作数据库。
- 白板数据通过 `BoardService` 或适配器读写。

### 保存与恢复

可评估保留：

- 内容指纹检查。
- 原子文件写入。
- 保存队列。
- 冲突提示。
- 恢复副本。
- 迁移 shadow/backup/确认等安全模式。

迁入要求：

- 保存协调器按工作区、对象和面板登记，不能继续只有全局单槽焦点。
- 笔记和白板分别维护版本。
- Agent 写入和用户写入都走相同的冲突规则。
- 外部文件变化不能只在下次保存时才发现。

### 数据模型

可保留的概念：

- 工作区身份。
- 资源身份。
- 引用目标。
- 画布位置与展示配置。
- 附件和外部文件引用。
- 缺失文件与恢复状态。

不直接保留的限制：

- 所有白板对象必须是外部资源卡片。
- 只有一个活动工作区状态。
- 只有一个笔记焦点视图。
- 视图名称决定产品导航。
- 历史命名决定新项目包结构。

## 3. 不应迁移的内容

- 旧应用的根路由和完整应用壳。
- 旧标题栏、设置面板和窗口控制逻辑。
- 旧产品全局快捷键注册。
- 旧总控制器的单活动白板/笔记状态。
- 旧项目的品牌色、产品名称、CSS 命名和 localStorage key。
- 旧项目中重复的领域文件副本。
- 已经被后端冻结或拒绝的遗留写入路径。
- 没有数据样本和回滚方案的批量删除/重命名脚本。

## 4. 数据迁移清单

迁移前需要分别盘点：

| 数据类别 | 处理要求 |
| --- | --- |
| 笔记正文 | 保留内容、标题、编码和相对关系；转换后校验正文摘要 |
| 白板原生对象 | 映射对象类型、几何、样式、层级和对象 ID |
| 白板引用 | 校验目标笔记存在；目标缺失时保留占位 |
| 附件 | 保留文件、引用路径和可用性；缺失附件不能静默丢弃 |
| 资源索引 | 重新生成或转换，但不能作为正文真源 |
| 应用草稿 | 单独读取和转换，不能假设随工作区目录自动迁移 |
| 阅读与视图状态 | 可以作为可选偏好迁移，不能阻塞正文和白板迁移 |
| 恢复副本 | 保留必要恢复记录，不能在迁移前清空 |

数据库或文件迁移必须考虑正在写入的日志、临时文件和恢复记录。只复制一个正在写入的数据库主文件不等于一致性备份。

## 5. 新旧代码的工作方式

推荐流程：

1. 在新项目定义目标接口。
2. 为接口写内存适配器和测试。
3. 从旧项目提取一个能力。
4. 写目标模型转换器。
5. 用测试数据验证结果。
6. 接入真实存储。
7. 通过验收后再迁移下一个能力。

不要先把旧项目目录全部复制过来，再试图删除不需要的部分。那会把旧外壳、全局事件、命名和隐含状态一起带入新项目。

## 6. 迁移完成的判断

只有满足以下条件，才可以认为某项能力已经迁移完成：

- 新项目可以单独启动和测试。
- 新项目不依赖旧项目运行中的进程或旧应用壳。
- 真实数据经过副本迁移后可读写。
- 保存失败和冲突行为有测试。
- 新项目的 Agent 占位或真实运行时都通过同一应用服务访问内容。
- 旧项目不再是该能力的唯一运行入口。
