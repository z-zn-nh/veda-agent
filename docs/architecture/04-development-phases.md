# 04 开发阶段

## 阶段 0：建立新目录与命名规则

目标：创建新项目骨架，不引入旧产品名称。

任务：

- 使用中性项目目录和包名占位符。
- 建立单一构建入口。
- 建立 TypeScript 基础配置和测试命令。
- 添加 `contracts`、`workspace`、`runtime`、`features`、`ui`、`platform` 目录。
- 确定新项目所有 CSS 前缀、localStorage key、数据库标识均不使用旧名称。
- 增加 README，明确产品名暂未确定。

完成标准：空项目可安装、类型检查、运行开发服务器，且不存在旧产品品牌标识。

## 阶段 1：核查 pi 与 Haze，建立占位适配器

任务：

- 确认具体 pi 代码基础之前，不写真实 Agent 绑定。
- 建立 `AgentRuntimeAdapter` 和不可用/模拟实现。
- 确认 Haze 的真实包名、版本、平台支持和 API。
- 建立本地 Haze 适配层；未确认时使用降级材质。
- 记录桌面容器候选及 TUI/GUI 通信方案，不在没有依据时定案。

完成标准：GUI 能显示 Agent 占位面板；Haze 能启动或明确降级；运行日志清晰说明运行时尚未接入。

## 阶段 2：实现 GUI 宿主和任意分栏

任务：

- 实现顶部工具栏。
- 实现 `PaneRegistry` 和 `PanelRenderer`。
- 实现单栏、双栏、多栏的分割树。
- 实现横向/纵向分割、比例调整、标签组、关闭与恢复。
- 实现面板焦点和快捷键路由。
- 使用模拟 Agent、模拟笔记和模拟白板面板验证宿主。

完成标准：至少三栏可以自由组合；可以并排打开两个同类面板；没有固定的 Agent 左栏或工具右栏假设。

## 阶段 3：实现不依赖 Agent 的工作区、笔记和白板

任务：

- 创建和打开工作区。
- 创建、编辑、保存、重开笔记。
- 创建、编辑、保存、重开白板。
- 支持白板原生对象。
- 支持笔记引用对象。
- 处理未保存、保存中、保存失败和恢复状态。

完成标准：不配置模型、不启动 Agent 也能完整使用笔记和白板。

## 阶段 4：接入旧工程的可复用能力

按能力迁移，不按旧项目外壳迁移：

- 先迁编辑器基础能力和内容转换。
- 再迁画布渲染与交互算法。
- 再迁保存保护、内容指纹和恢复副本。
- 最后迁资源、附件、预览和旧数据转换。

每次迁入后都要把能力接到新服务接口，不能让旧总控制器重新成为新项目核心。

完成标准：迁入的能力由新目录单独维护，旧工程只作为对照，双方不再长期修改同一功能的两份实现。

## 阶段 5：接入真实 Agent 运行时

前置条件：具体 pi 仓库、版本和运行方式已经确认。

任务：

- 实现具体 `AgentRuntimeAdapter`。
- 连接 TUI 和 GUI 到同一个会话执行器。
- 实现会话快照、事件游标、输入去重、取消和重连。
- 为 Agent 注册笔记、白板读写工具。
- 处理工具确认、执行失败和中断状态。

完成标准：TUI 启动或查看的会话，GUI 能看到并继续；GUI 断开不导致会话状态静默丢失。

## 阶段 6：数据迁移与工程收口

任务：

- 准备旧工作区副本和恢复副本。
- 迁移笔记、白板、附件、资源引用、应用草稿和状态。
- 校验对象数量、正文内容、引用目标和版本。
- 提供失败报告和回滚/重新执行策略。
- 完成新产品名称确定后的一次性命名替换。
- 旧项目只读归档，不在真实用户数据上直接试验。

完成标准：迁移副本可以打开、编辑、关闭、重开；失败时原始数据未被破坏。

## 严格禁止的开发方式

- 复制旧应用的整个 App 壳，再不断增加判断。
- 在两个客户端分别启动同一个 Agent 会话执行器。
- 让 Agent 直接写数据库表或 React 状态。
- 把白板限制为笔记卡片的排列视图。
- 把单栏、双栏、多栏实现成多个特殊页面。
- 在 Haze API 未确认前导入猜测包名。
- 在正式产品名未确定前把临时名写入包名、数据库标识或用户数据路径。
- 为了看起来“完成”而把模拟 Agent 标记成真实 Agent。
